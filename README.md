# rbffd2d

Проект предназначен для численного решения уравнений в частных производных
(PDE) методом RBF-FD в двумерных областях. Для дискретизации дифференциальных
операторов он предоставляет две основные возможности:

- **Поиск соседних узлов**:
  - Равноудалённые от точки вычисления узлы включаются в шаблон всей группой
    или не включаются вовсе.
  - Поиск учитывает невыпуклость области и наличие отверстий: выбираются
    только узлы, видимые из точки вычисления.
- **Вычисление весов RBF-FD с полиномиальным дополнением**:
  - Можно задать минимальное число соседей или степень полинома.
  - При необходимости шаблон автоматически расширяется.
  - Доступные радиальные базисные функции (RBF) описаны в библиотеке
    [rbf2d](https://github.com/AEArtemyev/rbf2d).

Эти функции объединены в одном проекте, поскольку при вычислении весов
иногда требуется расширить шаблон и повторно найти соседние узлы.
Это позволяет переиспользовать код и уже построенное дерево поиска,
ускоряя вычисления за счёт отсутствия повторного построения дерева.

Зависит от отдельной библиотеки [rbf2d](https://github.com/AEArtemyev/rbf2d).

## Установка

Из каталога проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install .
```

Нужны Python 3.10 или новее, Git и доступ к GitHub и PyPI.
Библиотека `rbf2d` устанавливается автоматически из ветки `main` на GitHub.

Для совместной разработки расположите проекты рядом и установите их
в редактируемом режиме:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ../rbf2d "numpy>=1.23" "scipy>=1.9"
.venv/bin/python -m pip install --no-deps -e .
```

Здесь зависимости устанавливаются первой командой. Флаг `--no-deps`
во второй сохраняет локальный `rbf2d` вместо установки версии из GitHub.

## Использование

Ядра находятся в `rbf2d`, функции для RBF-FD — в `rbffd2d`.

```python
import numpy as np
from rbf2d import PHS
from rbffd2d import find_neighbors, build_weights

x, y = np.meshgrid(np.linspace(-1, 1, 5), np.linspace(-1, 1, 5))
nodes = np.column_stack((x.ravel(), y.ravel()))
neighbors, weights = build_weights(nodes, PHS(3), poly_order=2)
# values — значения функции в узлах nodes
# dxx_i = values[neighbors[i]] @ weights[i][:, 3]
```

`find_neighbors(query_data, search_data=None, usage="polyOrder", ...)`
возвращает список массивов индексов с нуля. Без `search_data` поиск идёт
среди `query_data`. Режим `stencilSize` задаёт размер через `stencil_size`,
а `polyOrder` — через `poly_order` и `rho` (по умолчанию 2.5).
Включаются все соседи до расстояния последнего обязательного соседа плюс
`tol` (по умолчанию `1e-6`), включая саму точку.

`build_weights` возвращает соседей и список матриц весов со столбцами
`[f, dx, dy, dxx, dyy, dxy]`. В режиме `stencilSize` степень выбирается
по начальному числу соседей, в `polyOrder` сохраняется заданная степень.
Если полиномиальная матрица имеет недостаточный ранг, шаблон расширяется
до следующего соседа вместе со всей граничной оболочкой и допуском `tol`.
При расширении степень полинома не меняется. Если все узлы исчерпаны,
возникает `numpy.linalg.LinAlgError`.

Точки вычисления могут отличаться от узлов, среди которых ищутся соседи:

```python
query = np.array([[0.1, 0.2], [-0.3, 0.4]])
neighbors, weights = build_weights(query, PHS(3), search_data=nodes)
```

Индексы соседей в этом случае относятся к строкам `search_data`.
Без `search_data` или при пустом массиве поиск идёт среди точек вычисления.

Для повторных вычислений на одном облаке можно заранее построить дерево
и передавать его в `build_weights` или `find_neighbors`:

```python
from scipy.spatial import cKDTree

tree = cKDTree(nodes, copy_data=True)
neighbors, weights = build_weights(query, PHS(3), tree=tree)
```

При передаче `tree` координаты узлов берутся из `tree.data`, и индексы
соседей относятся к его строкам. Параметры `search_data` и `tree`
нельзя передавать одновременно. Координаты, на которых построено дерево,
нельзя изменять; `copy_data=True` отделяет их от исходного массива `nodes`.
Одно дерево используется для первоначального поиска и всех расширений
шаблонов. Без параметра `tree` оно строится один раз за вызов.

### Поиск с учётом области

Для невыпуклых областей и областей с отверстиями установите необязательную
зависимость Shapely:

```bash
.venv/bin/python -m pip install '.[geometry]'
```

Передайте один внешний контур и контуры отверстий через `shapely.Polygon`:

```python
import numpy as np
from scipy.spatial import cKDTree
from shapely import covers, points
from shapely.geometry import Polygon
from rbf2d import PHS
from rbffd2d import find_neighbors, build_weights

domain = Polygon(
    [(0, 0), (4, 0), (4, 4), (0, 4)],
    holes=[[(1, 1), (2, 1), (2, 2), (1, 2)]],
)
x, y = np.meshgrid(np.linspace(0, 4, 9), np.linspace(0, 4, 9))
nodes = np.column_stack((x.ravel(), y.ravel()))
nodes = nodes[covers(domain, points(nodes))]
query = np.array([[0, 0], [0.5, 1.5], [3, 3]])
tree = cKDTree(nodes, copy_data=True)
neighbors = find_neighbors(query, tree=tree, domain=domain)
neighbors, weights = build_weights(query, PHS(3), tree=tree, domain=domain)
```

Здесь `nodes` и `query` должны принадлежать заданной области или её границе.
Без `domain` сохраняется прежний евклидов поиск, не требующий Shapely.
С областью выбираются ближайшие по евклидову расстоянию **видимые** узлы:
весь отрезок от точки вычисления до соседа должен лежать в области вместе
с её границей. Касания вершин и участки вдоль рёбер разрешены; проход через
внутренность отверстия или внешнее пространство запрещён. Взаимная видимость
соседей между собой не требуется. Расстояния внутри RBF и формулы производных
не меняются.

Равноудалённые видимые узлы включаются всей группой, поэтому размер шаблона
может превышать заданный минимум. Включаются все видимые узлы до расстояния
последнего обязательного соседа плюс `tol`. Этот допуск не меняет геометрию
и не разрешает проходить через тонкие препятствия. Сам узел также входит
в шаблон, если он присутствует в поисковом наборе.

Полигон должен быть непустым, валидным и двумерным. Невалидная геометрия
и точки вне области вызывают ошибку без автоматического исправления.
Нехватка видимых узлов при начальном поиске вызывает `ValueError`.
Расширение при дефиците ранга также идёт полными оболочками только видимых
узлов; их исчерпание вызывает `numpy.linalg.LinAlgError`.

Один объект `domain` и одно дерево можно использовать повторно. Полигон
подготавливается для быстрых проверок видимости; его координаты не меняются.
Исследование влияния касаний на PDE-решения и будущая оптимизация для
выпуклых областей записаны в [ADR](docs/adr/0001-visible-neighbors.md).

### Вычисление весов на заданном шаблоне

`compute_weights(points, col_point, rbf, poly_order=2)` вычисляет веса
на явно заданном шаблоне `points` формы `(N, 2)` в точке `col_point`
формы `(2,)`. Возвращается матрица `(N, 6)` с теми же столбцами;
порядок строк соответствует `points`. Поиск соседей и расширение шаблона
не выполняются.

```python
from rbffd2d import compute_weights

w = compute_weights(nodes, [0.1, 0.2], PHS(3), poly_order=2)
```

Обе функции центрируют координаты и решают расширенную систему
с полиномиальным дополнением. Блоки системы масштабируются по максимальным
абсолютным значениям ядра и каждого столбца полиномов; это не меняет
математическое решение и не является регуляризацией. Неопределённые значения
ядра вызывают `ValueError`, вырожденная система — `numpy.linalg.LinAlgError`.
Полный ранг полиномиальной матрицы не гарантирует невырожденность всей системы.

`monomial_exponents(m)` возвращает степени всех мономов суммарной степени
до `m`: сначала по суммарной степени, затем по возрастанию степени `x`.
Полиномы и функции выбора размера и степени импортируются из `rbffd2d`.

`get_poly(x, y, exps)` вычисляет мономы, а `get_poly_x`, `get_poly_y`,
`get_poly_xx`, `get_poly_yy`, `get_poly_xy` — их производные.
Строки `exps` задают степени `[a, b]` мономов `x**a * y**b`.
Последняя ось результата соответствует строкам `exps`;
остальные оси определяются broadcasting координат.

```python
from rbffd2d import get_poly, get_poly_xx

exps = [[0, 0], [1, 0], [0, 1], [2, 0], [1, 1], [0, 2]]
values = get_poly([0, 1], [0, 2], exps)  # (2, 6)
dxx = get_poly_xx(0, 0, exps)           # [0, 0, 0, 2, 0, 0]
```

`eval_monomial_deriv(exps, x0, y0, ix, iy)` вычисляет частные производные
произвольного порядка для мономов произвольной степени. Степени задаются
в `exps`, порядки производных — неотрицательными целыми `ix`, `iy`.
Последняя ось результата соответствует мономам; координаты поддерживают
broadcasting.

`get_poly*` — явные реализации для значений и производных до второго порядка.
`eval_monomial_deriv` обобщает их на произвольные порядки производных.
При соответствующих `ix`, `iy` результаты совпадают по значениям, форме
и порядку мономов. Все эти функции поддерживают мономы произвольной степени.

| Вызов                                   | Эквивалент                |
| --------------------------------------- | ------------------------- |
| `eval_monomial_deriv(exps, x, y, 0, 0)` | `get_poly(x, y, exps)`    |
| `eval_monomial_deriv(exps, x, y, 1, 0)` | `get_poly_x(x, y, exps)`  |
| `eval_monomial_deriv(exps, x, y, 0, 1)` | `get_poly_y(x, y, exps)`  |
| `eval_monomial_deriv(exps, x, y, 2, 0)` | `get_poly_xx(x, y, exps)` |
| `eval_monomial_deriv(exps, x, y, 0, 2)` | `get_poly_yy(x, y, exps)` |
| `eval_monomial_deriv(exps, x, y, 1, 1)` | `get_poly_xy(x, y, exps)` |

Функция возвращает производные отдельных мономов. Для полинома нужно
умножить результат на вектор коэффициентов в том же порядке, что и `exps`:

```python
from rbffd2d import eval_monomial_deriv

# p(x, y) = 3*x**5*y**4 + 2*x**3*y**2
exps = [[5, 4], [3, 2]]
coefficients = [3, 2]
derivative = eval_monomial_deriv(exps, 2, -3, 3, 2) @ coefficients  # 77784
```

`falling_factorial(n, k)` вычисляет падающий факториал для неотрицательных
целых `n` и `k`; `n` может быть массивом. При `n < k` возвращается ноль,
при `k = 0` — единица. Обе функции импортируются из `rbffd2d`.

`get_rbf_fd_stencil_size(m, d, rho=2.5, mode="stable")` возвращает
`(n, Nm)`: число соседей и число мономов `Nm = C(m+d, d)`.
В режиме `min` число соседей равно `Nm`, в `stable` — `ceil(rho*Nm)`.

`get_poly_order(n, d, rho=2.5, mode="stable")` возвращает наибольшую степень,
для которой `C(m+d, d) <= n/rho`; режим `max` использует `n` вместо `n/rho`.
Поддерживаются размерности 2 и 3. При `n/rho < 1` в режиме `stable`
возникает `ValueError`. Название режима `stable` не гарантирует устойчивость.
