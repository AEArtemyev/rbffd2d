# Domain docs

This repo uses a single-context layout:

- `GLOSSARY.md`: domain vocabulary at the repo root.
- `docs/adr/`: architecture decision records.

Before exploring, read the glossary if present and ADRs relevant to
the area being changed. If these files do not exist, proceed silently.
The domain-modeling skill creates them when terms or decisions are resolved.

Use the glossary's terms in issues, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the term or note the gap
for domain-modeling.

Explicitly identify any proposal that contradicts an existing ADR,
including the ADR reference and the reason to revisit it.
