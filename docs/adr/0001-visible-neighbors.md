# Прямая видимость при выборе соседних узлов

Для плоской 2D-области с явно заданными полигональными границами включаем
в шаблон только узлы, видимые из точки вычисления: весь соединяющий отрезок
должен лежать в области вместе с её границей. Это правило действует и при
расширении RBF-FD-шаблона. Формулы RBF и их декартовых производных сохраняют
евклидово расстояние.

От ранжирования по кратчайшему пути внутри области отказались: оно допускает
включение скрытых препятствием узлов при расширении шаблона. Такие узлы могут
принадлежать другой локальной части решения PDE; малое евклидово расстояние
не гарантирует применимость общей локальной гладкой аппроксимации.
Различие значений решения само по себе не означает ошибку, и прямая видимость
сама по себе не гарантирует точности или устойчивости RBF-FD.

Сохраняем оба режима: без описания области используется существующий
евклидов поиск, при передаче области — поиск с прямой видимостью.
Так существующие вызовы продолжают работать без изменений.

Область передаётся необязательным параметром `domain` в `find_neighbors`
и `build_weights` как объект `shapely.Polygon`. Существующий параметр `tree`
сохраняется. Один объект области и одно дерево можно переиспользовать.
Невалидная геометрия и точки вычисления или поисковые узлы вне области
отклоняются с ошибкой. Автоматического исправления геометрии, удаления
узлов или привязки точек к границе нет. Граничные точки допустимы.

Первый вариант поддерживает один внешний контур с отверстиями.
Подготовленные данные должны переиспользоваться при многократных запросах
с неизменными геометрией и облаком узлов.

Видимость проверяем между точкой вычисления и каждым кандидатом в соседи.
Взаимная видимость всех пар узлов шаблона не требуется.

Среди видимых узлов сохраняем евклидов порядок и полные оболочки расстояний:
равноудалённые допустимые узлы включаются все вместе либо не включаются.
Для начального поиска порог — расстояние до k-го видимого узла плюс `tol`,
где k определяется существующими параметрами размера шаблона. Поэтому
фактический размер может превышать k. Расширение при дефиците ранга также
добавляет следующую полную оболочку видимых узлов с тем же допуском.
Скрытый узел не включается даже при совпадении расстояния с видимым.
Сохраняем порядок по расстоянию, затем по индексу, и включение самой точки,
если она присутствует среди поисковых узлов.

`tol` относится только к отбору по расстоянию. Не используем его для
геометрических проверок, расширения области или разрешения прохода через
препятствия. Отдельный геометрический допуск пока не вводим.

При нехватке видимых узлов вычисление завершается ошибкой. При дефиците
ранга полиномиальной матрицы шаблон расширяется только видимыми узлами.
Если доступные узлы исчерпаны, вычисление также завершается ошибкой;
автоматического перехода к скрытым узлам или понижения степени нет.
Полный ранг полиномиальной матрицы не гарантирует невырожденности всей
расширенной системы RBF-FD.

Разрешаем граничные узлы и прохождение вдоль рёбер, если отрезок нигде
не выходит из области. Пересечение внутренности отверстия или внешнего
пространства запрещено. Для выпуклой области при узлах внутри неё или на
границе геометрический фильтр не должен менять результат прежнего поиска.
Практический исходный пример — единичный квадрат, на котором пользователь
уже получал удовлетворительные решения без геометрического фильтра.
Это критерий совместимости, а не доказательство для невыпуклых областей.

Касание промежуточной вершины также разрешаем, если отрезок нигде не выходит
из области. Используем Shapely как необязательную зависимость для режима
с областью. Предикат `covers(domain, segment)` выражает единое правило
принадлежности всего отрезка области вместе с границей, без самостоятельного
разбора всех видов касаний и пересечений. Режим без области не должен
требовать установки Shapely.

Семантика предиката: [документация Shapely covers](https://shapely.readthedocs.io/en/stable/reference/shapely.covers.html).

Вопрос для исследования: влияние промежуточных касаний вершин на точность
и сходимость PDE-решения для RBF-FD, особенно около невыпуклых углов и при
разных граничных условиях. Разрешение касания не гарантирует гладкости
решения около угла; запрет может обеднять шаблон. Успешный опыт на выпуклом
квадрате не разрешает этот вопрос для невыпуклой геометрии.

Основание для исследования: [Jacquemin и Bordas (2021)](https://doi.org/10.1002/nme.6703)
изучают видимость и влияние углового порога на ошибку коллокационного метода
GFD. Это аргумент в пользу проверки граничной политики, а не доказательство
её оптимальности для RBF-FD.
